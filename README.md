# 🎧 Spotidrome

Десктоп-клиент для **Navidrome** (Subsonic / OpenSubsonic API), максимально похожий на Spotify:
тёмная тема, зелёный акцент, боковая медиатека, крупные обложки-hero с динамическим градиентом,
нижний плеер, очередь справа и полноэкранный режим «Сейчас играет» с синхронным текстом.

![Spotidrome](assets/icon.png)

## Управление треком снаружи окна

Чтобы не открывать приложение ради «дальше / пауза / назад», управление
вынесено в системные элементы. Состояние плеера renderer отдаёт в main по IPC
(`player:state`), команды приходят обратно по каналу `media-key`
(`electron/mediaControls.cjs`).

- **Windows** — кнопки на превью в панели задач (thumbnail toolbar): наведите
  курсор на значок Spotidrome, и под миниатюрой окна появятся, как в Spotify,
  пять кнопок: ♥ / 👎 / ◀◀ / ▶❚❚ / ▶▶ — «в любимые», «больше не играть»,
  назад, пауза-пуск, вперёд. Сердце показывает текущее состояние: контур —
  трека нет в любимых, зелёное залитое — уже добавлен. Палец вниз так же:
  контур — обычный трек, залитый красный — трек в исключённых. Нажатие
  переключает; дизлайк заодно выкидывает трек из очереди и включает
  следующий. Больше семи кнопок Windows не принимает — запас есть. Там же подсказка с названием
  трека, бейдж «играет/пауза» поверх значка и полоса прогресса по значку.
- **Linux** — MPRIS (D-Bus): контролы появляются в медиа-виджете GNOME/KDE, в
  апплетах громкости, на медиаклавишах и в панелях, умеющих MPRIS-превью;
  прогресс по значку работает в Unity-совместимых панелях. Обложка отдаётся из
  дискового кэша (`userData/covers`).
- **macOS** — меню в доке (правый клик по значку).
- **Везде** — иконка в трее: подсказка с текущим треком и меню
  «Предыдущий / Пауза / Следующий / В любимые / Больше не играть / Показать /
  Выход» (два последних пункта — с галочкой текущего состояния), клик по
  значку прячет и показывает окно. Те же пункты продублированы в меню дока
  на macOS.

**Почему кнопок может не быть и как это чинится.** Windows принимает кнопки
превью (`ThumbBarAddButtons`) только у окна, которое уже показано и имеет
кнопку в панели задач. Наше окно создаётся скрытым (`show: false`, показ по
`ready-to-show`), поэтому ранний вызов молча проваливался — а Electron после
него считал кнопки «уже добавленными» и дальше слал `ThumbBarUpdateButtons` в
пустоту: кнопки не появлялись до конца сессии. Теперь регистрация идёт только
после события `show`, результат вызова проверяется, при отказе делается до 12
повторов с нарастающей паузой, а на `show` / `restore` / `focus` кнопки
перерегистрируются (например, после перезапуска `explorer.exe`). Плюс задан
`app.setAppUserModelId('app.spotidrome.desktop')` — без него Windows иногда не
связывает окно с кнопкой в панели задач.

Проверить состояние можно в «О программе» → «Управление снаружи окна»:
там видно, приняла ли система кнопки («включены» / «ждём»), есть ли значок в
трее и работает ли MPRIS. В консоли main-процесса при успехе печатается
`[taskbar] кнопки на превью окна зарегистрированы`.

Кнопки автоматически гаснут, когда действие недоступно (нет очереди, нет
предыдущего трека, ничего не играет). Если в системе нет D-Bus или области уведомлений, всё
молча деградирует — приложение продолжает работать.

Реализация: `electron/mediaControls.cjs` (панель задач, трей, док, MPRIS),
`electron/mediaIcons.cjs` (иконки вшиты как data URL, чтобы работать внутри
`app.asar`), `src/lib/desktopMedia.js` (отдаёт состояние, не чаще раза в
секунду). MPRIS подключён как **опциональная** зависимость `mpris-service`.


## Сборка под Linux

Собирается и проверено на Debian 13 / Node 20 (electron-builder 25, Electron 32):

```bash
npm install
npm run dist:linux     # vite build + electron-builder --linux AppImage deb tar.gz
```

Готовые артефакты складываются в `release/`:

| Файл | Размер | Как запускать |
|---|---|---|
| `Spotidrome-1.0.0.AppImage` | ~108 МБ | `chmod +x` и запустить (нужен FUSE; иначе `--appimage-extract-and-run`) |
| `spotidrome_1.0.0_amd64.deb` | ~74 МБ | `sudo apt install ./spotidrome_1.0.0_amd64.deb` |
| `spotidrome-1.0.0.tar.gz` | ~101 МБ | распаковать и запустить `./spotidrome` |
| `release/linux-unpacked/` | ~280 МБ | распакованная сборка для отладки |

Зависимости `.deb` (ставятся автоматически): `libgtk-3-0, libnotify4, libnss3,
libxss1, libxtst6, xdg-utils, libatspi2.0-0, libuuid1, libsecret-1-0`.
Пакет кладёт приложение в `/opt/Spotidrome`, ярлык в
`/usr/share/applications/spotidrome.desktop` и иконку в `hicolor`.

Полезно знать:
- сборка **кросс-платформенная только частично**: с Linux нормально собираются
  Linux-цели, для Windows нужен Wine, для macOS — сама macOS;
- `.deb`/`.rpm` требуют заполненных `author.email`, `homepage` и
  `build.linux.maintainer` в `package.json` — без них electron-builder падает;
- ARM: `npm run dist:linux -- --arm64` (или `--armv7l`);
- сборка тянет ~110 МБ бинарей Electron в `~/.cache/electron*`, первый прогон
  дольше остальных.


## NixOS: запуск и сборка

На NixOS обычный `npm install && npm run dist:linux` ломается: в системе нет FHS,
и скачанные npm-бинарники (`electron`, `app-builder-bin`, `esbuild`, `mksquashfs`
из appimagetool, `ruby` внутри `fpm`) не находят `/lib64/ld-linux-x86-64.so.2`
и системные `.so`. В репозитории лежит всё, чтобы это обойти:

| Файл | Зачем |
|---|---|
| `shell.nix` | `nix-shell`, `nix-shell -A fhs`, `nix-build -A app` |
| `flake.nix` | `nix develop`, `nix build .#spotidrome`, `nix run .#fhs` |
| `nix/shells.nix` | dev-окружение и FHS-окружение (список библиотек) |
| `nix/package.nix` | `buildNpmPackage`: настоящий пакет с ярлыком и иконкой |

### 1. Разработка — Electron из nixpkgs

```bash
nix-shell            # либо: nix develop
npm install          # ELECTRON_SKIP_BINARY_DOWNLOAD=1 уже выставлен
npm run start:nix    # Vite + Electron (переменная $ELECTRON_BIN)
```

Окружение даёт Node 22 (`nodejs_20` из nixpkgs выпилен — EOL 30.04.2026), Python 3
и Electron из nixpkgs, а также переменные:

- `ELECTRON_SKIP_BINARY_DOWNLOAD=1` — npm не тянет свой бинарник, он всё равно не запустится;
- `ELECTRON_OVERRIDE_DIST_PATH` — распакованный Electron для electron-builder;
- `ELECTRON_BIN` — путь к запускаемому Electron, его использует `npm run start:nix`.

Только фронтенд (`npm run dev`, http://localhost:5173) работает и без всего этого.

### 2. Установщики (AppImage / deb / tar.gz) — FHS-окружение

`buildFHSEnv` создаёт внутри chroot привычные `/usr/lib` и `/lib64`, поэтому
electron-builder и его скачанные утилиты работают как на Ubuntu:

```bash
# интерактивно
nix-shell -A fhs                 # либо: nix develop .#fhs
npm install && npm run dist:linux

# одной командой (у nix-shell --run с FHS команда игнорируется — это нормально)
nix run .#fhs -- -c "npm install && npm run dist:linux"
```

Проверено на месте: получаются `Spotidrome-1.0.0.AppImage` (108 МБ),
`spotidrome_1.0.0_amd64.deb` (74 МБ) и `spotidrome-1.0.0.tar.gz` (102 МБ).
В `targetPkgs` пришлось добавить неочевидное — если правите список, не выкидывайте:

| Пакет | Без него падает |
|---|---|
| `zlib`, `xz`, `lz4`, `zstd`, `bzip2` | `mksquashfs: libz.so.1: cannot open shared object file` при сборке AppImage |
| `libxcrypt-legacy` | `ruby` внутри `fpm`: `libcrypt.so.1: cannot open shared object file` при сборке `.deb` |
| `binutils` | `fpm`: `Need executable 'ar' to convert dir to deb` |
| `fuse` | запуск получившегося AppImage |

### 3. Настоящий пакет Nix — `nix build`

```bash
nix build .#spotidrome        # либо: nix-build -A app
./result/bin/spotidrome
```

`nix/package.nix` — это `buildNpmPackage`: `npm ci` из `package-lock.json`,
`vite build`, затем `npm prune --omit=dev`, а сверху `makeWrapper` над
`${electron}/bin/electron` с путём к приложению. В результат попадают
`bin/spotidrome`, `share/applications/spotidrome.desktop` (с
`StartupWMClass=Spotidrome`, чтобы значок в доке не двоился) и иконка в `hicolor`.
Сам каталог приложения ~16 МБ: Electron берётся из nixpkgs, а не копируется внутрь.

Установить в систему:

```nix
# configuration.nix
environment.systemPackages = [ inputs.spotidrome.packages.${pkgs.system}.spotidrome ];
```

Два момента:

- **`npmDepsHash`** в `nix/package.nix` привязан к `package-lock.json`. После любого
  изменения зависимостей подставьте `lib.fakeHash`, запустите сборку и скопируйте
  правильный хеш из текста ошибки (`specified: … got: …`).
- Каталог лучше держать под git (`git init && git add -A`): иначе flake копирует в
  store весь каталог целиком, вместе с `node_modules` и `release`.

### Версия Electron

В nixpkgs-unstable сейчас `electron-43.4.1`, приложение писалось под 32.3.3 —
API, которое используется (thumbar, tray, MPRIS через `mpris-service`, `cover://`),
совместимо. Если нужна ровно ветка 32.x, запиньте старый nixpkgs и разрешите
устаревший пакет:

```nix
nixpkgs.config.permittedInsecurePackages = [ "electron-32.3.3" ];
```

### Чужой AppImage на NixOS

Если вы скачали `Spotidrome-1.0.0.AppImage` (собранный где-то ещё), запускать так:

```bash
nix-shell -p appimage-run --run "appimage-run Spotidrome-1.0.0.AppImage"
# или системно:
#   programs.appimage.enable = true;
#   programs.appimage.binfmt = true;
```

### Альтернатива FHS — `nix-ld`

Чтобы обычные скачанные бинарники (в том числе `node_modules/electron`) работали
без chroot:

```nix
programs.nix-ld.enable = true;
programs.nix-ld.libraries = with pkgs; [
  alsa-lib at-spi2-atk at-spi2-core atk cairo cups dbus expat gdk-pixbuf glib gtk3
  libdrm libnotify libsecret libxkbcommon libgbm nspr nss pango udev
  xorg.libX11 xorg.libXcomposite xorg.libXdamage xorg.libXext xorg.libXfixes
  xorg.libXrandr xorg.libXtst xorg.libxcb xorg.libxshmfence
];
```

### Мелочи NixOS

- **Трей** в GNOME виден только с расширением AppIndicator (`gnomeExtensions.appindicator`);
  в KDE/XFCE/Waybar работает из коробки.
- **MPRIS** (кнопки на клавиатуре, виджеты плеера) требует сессионного D-Bus — в
  обычной графической сессии он есть, в `nix-shell` по SSH его может не быть, тогда
  Spotidrome просто молча пропускает MPRIS.
- Если Electron ругается на песочницу (`SUID sandbox helper`), запускайте
  `spotidrome --no-sandbox` — в пакете из nixpkgs это уже учтено.


## Возможности

**Несколько исполнителей у трека**
- Имена в списке треков, в плеере, в панели очереди и на полноэкранном экране
  кликаются **по отдельности**: «Yeat & Summrs» — две разные ссылки, разделитель
  («&», «feat.», запятая) остаётся обычным текстом и не подсвечивается
- Источник данных — OpenSubsonic-поля `artists` / `albumArtists` /
  `participants.artist` (их отдаёт Navidrome). Тогда подпись даже не приходится
  разбирать: имена берутся готовыми, а исходное написание сохраняется
- Если сервер их не прислал, подпись разбирается в три шага:
  1. знаки препинания — `, ; / | · •` (внутри имён почти не встречаются);
  2. явное участие — `feat.` `ft.` `featuring` `with` `vs`;
  3. спорные — `&` `+` `×` `x` `и` `and`: по ним режем, **только если** такого
     исполнителя целиком нет в библиотеке. Поэтому «Yeat & Summrs» превращается
     в две ссылки, а «Sable & Sons» остаётся одной — проверка идёт по имени
     исполнителя из `artistId` и поиском `search3`
- `artistId` трека **не раздаётся** первому имени: Navidrome кладёт туда
  исполнителя альбома, который может стоять в подписи вторым (именно из-за этого
  «Yeat & Summrs» раньше вело на Summrs). Каждое имя ищется отдельно, результаты
  кэшируются на сессию, ненайденное имя открывает поиск
- В контекстном меню трека вместо одного пункта появляется список «Перейти
  к исполнителю → …», и «Радио: …» строится по каждому участнику отдельно
- На вкладке «Об исполнителе» (полноэкранный плеер) сверху появляются чипы —
  переключение между участниками трека без ухода со страницы
- Подчёркивается **только имя под курсором**: старое правило
  `.t-artist:hover { text-decoration: underline }` подсвечивало всю ячейку, из-за
  чего четыре ссылки выглядели одной. Разделители некликабельны (`pointer-events: none`)
- Проверено на подписях `Quality Control feat. Quavo, Offset & Lil Yachty`,
  `Yeat & Summrs`, `Summrs, Sable & Sons`, `Sable & Sons feat. Yeat`, `A feat. B`
  и `A, B` — все они есть в демо-библиотеке

**Громкость**
- Шкала логарифмическая: положение ползунка возводится в степень 2.25, поэтому
  50% — это примерно −13 дБ, а не «почти максимум». Внизу шкалы наконец есть
  запас для тихой настройки
- Значение применяется **на лету**, пока тянете ползунок (раньше — только после
  отпускания); частота обновления привязана к кадрам, а на диск настройка
  сохраняется один раз, через 350 мс после последнего движения
- Колесо мыши над ползунком меняет громкость шагами по 4%, при наведении и
  перетаскивании показывается подсказка с процентами
- Перемотка по-прежнему срабатывает только при отпускании — поток не дёргается

**Оболочка окна**
- Кастомный тайтл-бар в духе актуального Spotify: окно без системной рамки
  (`frame: false`, на macOS — `hiddenInset` со сдвинутым «светофором»)
- Глобальная навигация в шапке: логотип, стрелки назад/вперёд, круглая кнопка «Главная»,
  крупное поле поиска по центру (`Ctrl/Cmd + K`, `L` или `/`), эквалайзер и меню аккаунта справа
- Свои кнопки свернуть / развернуть / закрыть на Windows и Linux, перетаскивание окна за шапку,
  двойной клик разворачивает, шапка приглушается когда окно не в фокусе
- При прокрутке страницы в контентной области проявляется липкая полоса с названием
  и компактной зелёной кнопкой воспроизведения

**Кэш обложек**
- URL картинок и стримов теперь стабильны: соль Subsonic-авторизации одна на сессию,
  поэтому работают и HTTP-кэш браузера, и наш кэш (раньше каждый рендер давал новый адрес)
- Три уровня: LRU в памяти (500 записей) → диск/Cache Storage → сеть
- В десктопе картинки лежат в `userData/covers` и отдаются по схеме `cover://`
  с `immutable`-заголовком; размер кэша ничем не ограничен — чистится только вручную
  кнопкой «Очистить» в настройках
- В браузере используется Cache Storage `spotidrome-covers-v1` + blob-URL
- Обложки ближайших 8 треков очереди подгружаются заранее — переключение без мигания
- Размер кэша и кнопка «Очистить» — в окне «Настройки»
- Если кэш почему-то не отдаёт картинку, клиент автоматически откатывается на прямой
  URL сервера: `<img>` перезапрашивает обложку и запись кэша инвалидируется,
  а неработающий `cover://` отключается на всю сессию после первой же проверки

**AutoDJ — бесконечная очередь**
- Тумблер в панели очереди, кнопка-антенна в плеере и клавиша `D`
- Когда впереди остаётся меньше N треков (3/5/10/20), клиент сам дописывает подходящие;
  очередь при этом не заканчивается — `next()` дозаправляет её на лету
- Режимы подбора: **Микс** (похожие + жанр + случайные), **Похожие** (`getSimilarSongs2`,
  с запасным вариантом через `getArtistInfo2` → `getTopSongs` близких артистов),
  **Исполнитель**, **Жанр**, **Любимое**, **Случайно**
- «Не повторять недавнее» помнит последние 500 автотреков; подбор не залипает
  на одном исполнителе (не больше половины порции)
- Автотреки помечены зелёной полоской и значком антенны; при выключении AutoDJ
  неигранный автохвост убирается, при смене режима — пересобирается
- «Радио»: в контекстном меню трека — «Радио по треку» и «Радио: исполнитель»,
  на странице артиста — кнопка «Радио». Запускает затравку и включает AutoDJ
- Настройки продублированы в окне «Настройки» и сохраняются между запусками

**Случайный трек — анимация «ставим пластинку»**

Сцена рисуется на canvas 2D (`src/lib/vinylScene.js`, компонент
`src/components/RandomVinyl.jsx`), фазы приходят из стора и привязаны к реальной
загрузке, а не к таймерам. Всё считается на `requestAnimationFrame` с
дельта-таймом, текстуры (дорожки винила, этикетка) генерируются процедурно
под текущий размер окна и DPR.

1. `idle` (700 мс) — пластинка падает на диск вертушки, тень под ней уплотняется
2. `spin` — раскрутка и вращение с «детонацией» (wow&flutter), анизотропный блик
   винила, пыль в луче света. Длится **ровно столько, сколько грузится трек**
   (минимум 1.4 с)
3. `balance` — если ответа нет дольше 2.6 с, тонарм зависает над краем и «ищет
   дорожку», подпись меняется на «Ищем дорожку…»
4. `settle` (900 мс) — тонарм по честной кинематике поворотного тонарма
   (угол считается теоремой косинусов, игла всегда точно на дорожке)
   опускается, в момент касания — вспышка и кольцевые волны по пластинке
5. `top` — камера наезжает на этикетку, пластинка останавливается и доворачивается
   ровно, бумажная этикетка кроссфейдом превращается в обложку трека
6. `expand` — круглую обложку подхватывает `<img>` и по WAAPI перелетает в
   обложку плеера, попутно превращаясь из круга в квадрат со скруглением

## Тексты песен: Navidrome + LRCLIB

Тексты собираются из двух источников (`src/lib/api.js` → `getLyrics`, вся сетевая часть — в `src/lib/lyrics.js`):

1. **Сервер.** `getLyricsBySongId` (OpenSubsonic) — структурированные строки с таймкодами из
   тегов трека или `.lrc` рядом с файлом; если их нет, старый `getLyrics?artist=&title=` — текст без таймкодов.
2. **LRCLIB** (`https://lrclib.net/api/get`, затем `https://lrclib.net/api/search`) — открытая база
   синхронизированных текстов без ключей и регистрации. Отвечает, когда на сервере текста нет вообще,
   и дописывает тайминг к несинхронному тексту из тегов (если слова совпадают).

Порядок и правила:

- свой **синхронный** текст с сервера всегда в приоритете — LRCLIB для такого трека не дёргается;
- запрос к LRCLIB идёт с названием и артистом, очищенными от «(Official Video)», «[Lyrics]»,
  «- 2011 Remaster», «feat. …»: точный `get` с альбомом и длительностью → `get` без них → `search`
  с выбором лучшего варианта (свой рейтинг: есть синхронизация, близость названия/артиста, разница длительности);
- **инструменталы** не выдумываются: если LRCLIB отвечает `instrumental`, так и пишется — «Инструментал»;
- ответы (и «не нашли тоже») кэшируются в `localStorage` на 80 треков, пустые — с протуханием за 4 дня;
- у LRCLIB вежливый лимит: **не чаще одного запроса в секунду**, очередь общая для всех треков,
  ответы `429`/`503` (`server busy`) повторяются один раз с паузой по `Retry-After`.

Интерфейс (вкладка «Текст» в полноэкранном плеере, клавиша `F`):

- активная строка белая, прошлые гаснут, будущие размыты; клик по строке перематывает;
- если в тексте есть метки слов (`<мм:сс.мс>` — расширенный LRC), подсвечиваются и сами слова;
- `−` / `+` сдвигают текст на 0.5 с (до ±30 с) — лечит треки с «тихим» началом или ремастер-сдвиг;
  значение видно в шапке, сброс — кликом по нему. Правка живёт в настройках и не требует нового запроса;
- в шапке — источник (`сервер` / `LRCLIB` / `демо`), ссылка на страницу текста и кнопка
  «найти заново» (обходит кэш; в демо-режиме это единственный способ увидеть работу LRCLIB).

Настройки (шестерёнка → «Тексты»):

| Переключатель | По умолчанию | Что делает |
|---|---|---|
| Тексты: база LRCLIB | включено | искать недостающие тексты в `lrclib.net` |
| Готовить тексты заранее | включено | при старте трека подтягивать тексты для следующих 3 треков очереди — текст готов до переключения |
| Поправка синхронизации | 0 с | глобальный сдвиг таймкодов; там же кнопка «Кэш» — сбросить кэш текстов |

## Что подправил сплошной аудит

Полный проход по кодовой базе (10,5 тыс. строк) — исправлены реальные дефекты,
каждый закрыт проверкой в `tools/test-audit.mjs` или `tools/e2e-audit.mjs`:

* **Удаление трека из плейлиста.** Индекс брался от видимой строки таблицы; если
  выше стоял исключённый (скрытый) трек, удалялся сосед сверху. Теперь трек
  ищется по `id` в исходном списке плейлиста.
* **Ошибки сервера при правке плейлиста.** `updatePlaylist` не смотрел на ответ и
  «успешно» добавлял треки в чужой или удалённый плейлист; теперь статус
  `subsonic-response` проверяется, а текст ошибки уходит в уведомление.
* **Зависание без ответа.** Запросы к серверу получили таймаут 20 с — раньше
  «проверка доступа» могла висеть бесконечно.
* **Эквалайзер.** Предусиление оставалось в тракте при выключенном эквалайзере
  (звук становился громче); при пересоздании аудио-графа полосы терялись.
  Теперь фильтры помнят последние значения и возвращают их при включении.
* **Очередь.** Удаление играющего трека из очереди останавливало звук — теперь
  включается следующий. Защита от исключённых треков в `next()` перечитывает
  очередь (AutoDJ успевал её дополнить).
* **Форматирование.** Длительность больше часа показывалась как `75:32`, размеры
  от 1 ТБ — как `undefined`, «59.7 мин» округлялось до «1 ч 60 мин».
* **Офлайн.** Лишние перечитания списка исключённых при скачивании могли стереть
  дизлайки из памяти; пустой или оборванный файл больше не считается скачанным;
  скачивание альбома выдаёт одно уведомление, а не по одному на трек.
* **Биографии исполнителей** приходили HTML'ом и вставлялись в DOM как есть —
  теперь это текст: теги вырезаются, `onerror`/`javascript:` невозможны.
* **Мелочи.** Клик по обложке в нижнем плеере не открывал полноэкранный режим
  (`onClick` терялся), страница жанра падала на `%` в адресе, альбом и плейлист
  крутили бесконечный спиннер при ошибке загрузки, слушатель `scroll` у
  контекстного меню копился, цвет обложки пересчитывался на каждой странице,
  колесо мыши над ползунком громкости ещё и прокручивало список.
* **Сохранение настроек** записывалось с задержкой 350 мс и терялось при быстром
  закрытии окна — добавлен сброс на `pagehide`/скрытии вкладки.
* **Электрон.** Имя офлайн-файла строилось из `id` трека без очистки (выход за
  папку кэша), редиректы скачивания не считались, а оборванная загрузка оставляла
  `.part`. Проверка схемы, лимит редиректов, удаление мусора.
* **Производительность.** Почти все компоненты подписывались на весь стор, поэтому
  отмечка времени проигрывания (4 раза в секунду) перерисовывала медиатеку,
  очередь, список треков и поле ввода поиска. Подписки стали точечными.
* **Разработка.** Политика безопасности в `index.html` блокировала HMR-сокет Vite;
  в дев-режиме `ws:`/`wss:` разрешены через `.env.development`, в сборке политика
  остаётся строгой.

## Виртуальные списки и «Недавнее»

**Виртуализация списков (`react-window`)**
- Порог — 60 строк (`VIRTUAL_FROM` в `src/components/TrackList.jsx`): короче —
  обычный рендер, ничего не меняется; длиннее — список собирается заново
- В большом плейлисте раньше в DOM жило до 100 тыс. узлов: 4000 строк × ~25 элементов.
  Теперь в DOM только видимые строки плюс запас (`overscanCount`), а `scrollHeight`
  равен полной высоте списка, поэтому полоса прокрутки честная
- `rowHeight` — не магическое число, а `row` из `DENSITY` (`src/lib/uiLayout.js`),
  из той же таблицы, что и CSS-переменная `--row-h`: компактный/обычный/просторный
  режимы и ползунок масштаба не разъезжаются со списком
- У `react-window` v2 нет привязки к чужому скролл-контейнеру (в отличие от
  `WindowScroller` из react-virtualized), поэтому у списка **свой** скроллбокс:
  высота считается до низа окна (`VList.jsx`), а при прокрутке страницы —
  пересчитывается, так что список занимает место уехавшего вверх героя
- Заголовок списка в виртуальном режиме перестаёт быть `sticky` (он и так над
  списком), а при заходе в огромный список сразу прокручивается к играющему
  треку (`scrollToRow`)
- Проверка: `npm run test:virtual:ui` (в DOM 10–20 строк из 4000, прокрутка
  12 шагов ~60 мс, двойной клик ставит в очередь весь список с нужным индексом)

**Автоматическая подгрузка страниц**
- Раньше список брался одной порцией с запасом: у кого фонотека больше порции,
  тот в «Недавних» видел только её начало. Теперь список растёт сам — дошли до
  края, и следующая страница приезжает без всяких кнопок
- Общий хук `src/lib/usePagedList.js`: сторожевой элемент внизу списка попадает
  в поле зрения (`IntersectionObserver`, запас 800 px) — тянем следующую порцию.
  Виртуальный список скроллится внутри себя, поэтому там вместо сторожа считаются
  отрисованные строки (`onRowsRendered` из `react-window`)
- Страницы: 36 альбомов в медиатеке, 60 треков в жанре и в поиске. Число 60 не
  случайное — это порог виртуализации: первая порция сразу больше него, поэтому
  список не перестраивается с обычного на виртуальный на второй странице
  (перестройка сбросила бы прокрутку наверх)
- Поколения запросов: сортировку или вкладку могли переключить, пока страница
  ехала, — ответ с чужим номером выбрасывается, в список не попадает ничего
  из прошлого запроса
- Склейка без повторов: сервер сортирует по живому полю, поэтому запись может
  приехать в двух соседних страницах — повторы отбрасываются по `id`
- Конец списка: страница пришла короче запрошенной — это последняя. Внизу
  появляется пометка «N альбомов — это все», и больше запросов не делается
- Проверка: `npm run test:paging:ui` (медиатека 36 → все 44 без повторов, смена
  сортировки начинает список заново, жанр «Hip-Hop» 60 → 74, поиск «a» → все 342)

**Экран «Недавнее» (`/recent`)**
- Своей истории прослушиваний у Subsonic нет (`scrobble` — только запись на
  сервер, `getRecentlyPlayed` не существует), поэтому история локальная:
  `src/lib/playHistory.js` + ключ `playHistory` в конфиге (переживает перезапуск,
  чистится при `logout`)
- Прослушивание засчитывается, когда трек звучал ~20 секунд (`MIN_LISTEN_SEC`)
  или доиграл до конца; повтор того же трека не дублируется, а поднимается наверх;
  потолок — 800 записей
- Один плоский список строк: заголовок дня («Сегодня», «Вчера», «12 мая» с годом
  для давних) + треки этого дня, с числом прослушиваний и длительностью; список
  виртуализирован так же, как плейлисты
- Фильтр по дням — «Сегодня / 7 дней / 30 дней / Всё»; рядом «Играть» (вся
  выборка), «Перемешать», «Играть день» у заголовка, «Очистить» с «Вернуть» в тосте
- `getNowPlaying` подключён: на экране показывается полоса «Сейчас играет» —
  что слушает этот же пользователь на других устройствах
- Полоса **обновляется сразу при переключении трека**, а не раз в минуту: свой
  трек берётся из плеера мгновенно (сервер узнаёт о переключении только когда
  начался стрим), а ответ `getNowPlaying` запрашивается через 0,4 и 2,5 с после
  переключения — он догоняет и добавляет остальные устройства. Своя строка с
  сервера отбрасывается, чтобы не мелькало устаревшее название
- Строка в истории — обычный `.track-row`: обложка, имена исполнителей со ссылками,
  альбом, «сколько назад» + контекст (откуда играли), длительность, крестик
  «убрать из истории» и контекстное меню
- В настройках — переключатель «История прослушиваний» и кнопка «Очистить»;
  выключенный переключатель историю стирает и больше не пишет
- Проверки: `npm run test:play-history` (офлайн) и `npm run test:recent:ui` (Playwright)

## Мультивыбор треков и порядок плейлистов

**Мультивыбор в любом списке треков (`src/components/TrackList.jsx`)**
- Выделение как в проводнике: **клик** — строка, **Shift + клик** — диапазон от
  последней, **Ctrl/Cmd + клик** — добавить или снять одну, **Ctrl/Cmd + A** —
  весь список, **Esc** — снять выделение
- Галочка в первой колонке снимает выделение со строки, не трогая остальные
- Над списком появляется панель: сколько выбрано и действия пачкой —
  **«Играть следующим», «В очередь», «В плейлист…», «В любимые»** и **«Удалить»**
  (последняя — там, где у списка есть удаление: плейлист, «Любимые треки»)
- То же самое есть в меню по правому клику: если строк выделено больше одной,
  меню показывает пачковые пункты со счётчиком и быстрый список своих плейлистов
- На странице «Любимые треки» пачка снимает сердечки (`setStarMany` — один тост
  на всю пачку, а не по тосту на трек), **Del** удаляет выделенное там, где это можно
- Удаление из плейлиста — **один запрос** `updatePlaylist` со списком
  `songIndexToRemove`, а не по запросу на трек. Номера строк таблицы не годятся
  (в ней скрыты исключённые треки), поэтому позиции считаются по исходному списку;
  если трек лежит в плейлисте дважды, удаляется только выделенная строка
- Список переехал (перезагрузили плейлист, убрали треки) — выделение снимается само:
  сравнивается состав строк, а не ссылка на массив, поэтому «Поиск» не сбрасывает
  выбор на каждый чих стора
- Работает и в виртуальном режиме: выделение считается в номерах строк, в DOM
  по-прежнему только видимая часть
- Проверка: `npm run test:multiselect:ui` (Playwright)

**Свой порядок плейлистов (перетаскиванием)**
- Плейлисты в медиатеке можно расставить как угодно: тяните строку мышью.
  Пока тянете, источник гаснет, а у цели видна полоса — **до** или **после**
  строки, смотря куда пришёлся курсор (верхняя или нижняя половина)
- Переставить можно и в сетке «Моя медиатека → Мои плейлисты» (там — левая или
  правая половина карточки), и в свёрнутой полосе медиатеки
- Порядок **один на всё приложение**: медиатека слева, сетка медиатеки, окно
  «Добавить в плейлист» — везде один и тот же порядок, он же переживает перезапуск
- Кидать можно только внутри своей группы: свои к своим, общие к общим,
  закреплённые — внутри закреплённого (там порядок задают закрепления).
  Альбомы и исполнители не переставляются
- Порядок **локальный** (`settings.playlistOrder`): Navidrome отдаёт плейлисты
  своим чередом, а Subsonic API не умеет переставлять их на сервере. Новые
  плейлисты, которых в списке ещё нет, просто встают в конец
- Вернуть как было — «Сбросить порядок плейлистов» в меню по правому клику
  на любом плейлисте медиатеки
- Логика — `src/lib/usePlaylistDnd.js` (общий хук для списка и сетки),
  порядок применяет `orderPlaylists()` в сторе

## Шапка, заголовок страницы и логотип

- **Слева сверху остались только стрелки** «назад / вперёд»: логотип и слово
  «Spotidrome» из верхней панели убраны (заодно исчезли и их стили)
- Заголовок в шапке (он проявляется при прокрутке) **принадлежит текущей
  странице**. Раньше `pageTitle` жил в сторе сам по себе: зашли в альбом или
  плейлист, вернулись на главную — и при прокрутке сверху всплывало название
  того альбома. Теперь `setUI` запоминает маршрут, с которого поставлены
  `pageTitle` / `pagePlay` / `heroColor` (`pageRoute`), а `Main` показывает их,
  только если маршрут совпал с текущим
- Маршрут запоминается в рендере `Main` (`setRouteNow`), то есть **до** эффектов
  страниц: страницы ставят заголовок уже под новый адрес. Плейлист, который
  грузится дольше, чем вы на нём остались, заголовок уже не проставит
  (страховка `alive` в `load`)
- Побочно починилось: кнопка «играть» в шапке больше не пропадала на страницах
  альбома, плейлиста и «Любимых» — раньше её стирал сброс при каждом переходе
- Проверка: `npm run test:uifixes:ui` (Playwright: нет логотипа, стрелки на месте,
  на альбоме — своё название и кнопка «играть», на главной — пусто, «сейчас
  играет» обновляется быстрее чем за 3 с; плюс доступность окон, списка и
  ползунков — см. «Аудит интерфейса»)
- Ещё: `npm run audit:ui:scan` — сканер интерфейса по всем страницам и окнам

## Аудит интерфейса (ui/ux)

Проход по всему интерфейсу с автоматическим сканером
`npm run audit:ui:scan` (`tools/e2e-ui-audit.mjs`): он ходит по всем страницам и
окнам на пяти ширинах (1440…720 px) и ищет типовые беды — вылезающие за экран
элементы, обрезанный без многоточия текст, кнопки меньше 24 px, кнопки без
доступного имени, картинки без `alt`, тусклый по WCAG текст, обрезку без
подсказки, повтор `id`, кнопку внутри кнопки и контент, припрятанный под нижним
плеером. Сейчас сканер не находит ничего; найденное починено:

* **Окна (настройки, эквалайзер, раскладка, «о программе», «добавить в плейлист»).**
  `Tab` уводил фокус в интерфейс под затемнением, окно «раскладка» не закрывалось
  по `Esc`, у кнопки «закрыть» не было имени. Появился общий хук
  `useModalFocus` (`src/lib/uiA11y.js`): ловушка `Tab`, закрытие по `Esc`,
  возврат фокуса на кнопку, которой окно открыли. Фокус получает само окно, а не
  первая кнопка — иначе пробел сразу её нажимал (в настройках это было
  «закрыть»)
* **Список треков** был доступен только мышью (`tabindex="-1"`): теперь до него
  можно дойти `Tab`, стрелки ходят по строкам, `Enter` играет выбранную
* **Ползунки** (`Slider`) получили `role="slider"`, `aria-valuenow` и управление
  стрелками / `Home` / `End` — громкость и перемотка двигаются с клавиатуры
* **Тумблеры** в настройках и раскладке были `div` с `onClick` — теперь это
  `<button role="switch">` с подписью
* **Мелкие цели:** иконки в плеере были 28×18 px, «Показать всё» — 16 px высотой,
  плашка папки — 23 px. Теперь не меньше 24–32 px, у всего есть видимый фокус
* **Текст, который не прочитать:** неактивные строки текста песни (контраст 2.75
  вместо 3), подпись источника текста, белые подписи на светлых карточках жанров
  (`#ff4632`, `#509bf5`) — под карточки добавлена тёмная подложка
* **Обрезка без подсказки:** названия и подписи в медиатеке, исполнитель и
  название в строках треков и в очереди теперь подписаны (`title`) — прочитать
  можно всплывающей подсказкой
* **Длинные слова в шапке:** «Исключённые треки» вылезали за край окна на 860 px —
  добавлены `min-width: 0` у колонки и перенос `overflow-wrap: anywhere`
* **Склонения:** «1 треков», «1 альбомов» — теперь через `songsWord`/`albumsWord`
* **Ссылки из текста:** заголовок секции, название трека в плеере, альбом в
  строке и в полноэкранном плеере были кликабельны только мышью — теперь это
  роли `link` с `Enter`/пробелом (helper `linkProps`)

Проверки: `npm run audit:ui:scan` — сам сканер (должен сказать «ничего»),
`npm run test:uifixes:ui` — регрессии по каждому пункту (ловушка фокуса, `Esc`,
имена кнопок, клавиатура в списке и на ползунке, ширина шапки, контраст жанров,
склонения).

## Очередь, полноэкранный плеер и узкое окно

* **Ручку панели «Очередь» почти нельзя было ухватить.** Ручка на 10 px
  вынесена за край панели, а у `.rightbar` стоял `overflow: hidden` — он её и
  обрезал: для мыши оставалась полоска в 1 px. Теперь подрезает содержимое сам
  список (`.rb-body`), а ручка живёт снаружи — тянуть так же легко, как
  медиатеку. Подрезание углов сохранилось.
* **Узкое окно ломало раскладку.** До 1180 px (а с масштабом 1.2 — и на 1400)
  панель очереди пряталась, но её колонка в сетке оставалась: справа чернела
  пустая полоса во весь экран. Хуже того, свёрнутый шаблон терял строку `title`,
  шапка уезжала в неявные ячейки, а центральный блок схлопывался в ноль — как
  раз то самое «всё стало чёрным». Теперь место считает `fitPanels()` в
  `src/lib/uiLayout.js`: очередь сначала ужимается (до 240 px), а когда и это не
  влезает — убирается вместе со своей колонкой; центральный блок всегда
  получает не меньше 360 px, шаблон всегда из трёх строк. Пересчёт идёт и при
  протяжке окна мышью.
* **Кнопки вверху полноэкранного плеера.** Круглая кнопка (40 px) была и
  границей клика: попасть мимо круга — промах. Теперь кнопка 44×44 со строго
  квадратной областью нажатия, а круг нарисован слоем внутри — попадаешь даже
  самым углом. Проверено во всех раскладках и на всех ширинах.
* **Кнопка «Свернуть приложение» в полноэкранном режиме** стоит перед выходом
  из него. В десктопе убирает в панель задач всё окно (Electron сначала выходит
  из полноэкранного режима окна — иначе на macOS вызов просто игнорируется).
  В браузере своего окна нет, поэтому сворачивается весь интерфейс: остаётся
  плашка «Spotidrome — развернуть», музыка продолжает играть, клик по плашке
  или `Esc` возвращают всё назад. Кнопка выхода из плеера называется «Выйти из
  полноэкранного режима (Esc)», чтобы две «свернуть» рядом не путались.
* **Кнопки не нажимались в собранном приложении.** У верхней панели стоит
  `-webkit-app-region: drag`, а в Electron это не про CSS, а про окно: клик в
  такой полосе уходит системе на перетаскивание и до страницы не доходит.
  В браузере свойство ни на что не влияет, поэтому баг был виден только в
  сборке — кнопки вверху полноэкранного плеера попадали в полосу (высотой
  `--titlebar-h`, 44…96 px) целиком или наполовину. Теперь, пока поверх открыт
  любой слой — плеер, настройки, эквалайзер, раскладка, «о программе»,
  «добавить в плейлист», контекстное меню или бросок кубика — на `<html>`
  ставится `data-overlay="on"` и перетаскивание снимается.
* **Кнопки окна в заголовке.** В полноэкранном режиме вместо бесполезного
  «развернуть» — выход из полноэкранного режима; сами кнопки стали шире (44 px)
  и выше (в тонкой полоске 30 px вместо 26).

Проверка: `npm run test:uifixes:ui` (ручка ловится всей полосой и тянет панель,
кнопка полноэкранного 44 px и попадается с угла, под слоем верхняя полоса не
таскает окно, «свернуть приложение» стоит перед выходом и сворачивает весь
интерфейс, плашка разворачивает его обратно, на восьми ширинах от 1440 до 820
раскладка не ломается) и `npm run audit:ui:scan`.

## Блокировка исполнителей

Раньше исключать можно было только отдельные треки («палец вниз»). Теперь
исполнителя можно исключить целиком — и его треки перестают попадаться.

**Где блокировать**

* **меню трека** (правый клик по строке, «Ещё» в полноэкранном плеере, меню
  альбома): пункт «Заблокировать: Имя» — по одному на каждого исполнителя,
  поэтому у «A feat. B» можно забанить кого-то одного;
* **страница исполнителя**: кнопка «Заблокировать» рядом с «В очередь»;
* **список**: «Настройки → Заблокированные исполнители → Список» или вкладка
  «Исполнители» на странице исключённых треков (`/disliked?tab=artists`).

**Что это меняет**

* треки такого исполнителя не приходят в AutoDJ, радио и случайный выбор —
  отсекаются ещё на отборе (`reject` в `pickAutoDj`), а не выкидываются после;
* «далее» по очереди перешагивает через них;
* при блокировке они сразу убираются из текущей очереди (если играл такой —
  включается следующий);
* в списках треки прячутся, когда включено «Скрывать их треки»
  (`settings.hideBanned`, по умолчанию да). Выключили — треки видно, но сами
  они по-прежнему не приходят;
* вручную включить такой трек можно всегда: бан запрещает подборки, а не
  доступ к фонотеке.

**Как считается.** Список живёт в настройках (`bannedArtists: [{ id, name, at }]`,
рядом с исключёнными треками). Сверка — в `src/lib/banned.js`: по имени без
учёта регистра и по `id`, причём по каждому исполнителю из подписи
(«A feat. B», «A, B») и по подписи целиком — на случай «Simon & Garfunkel»,
которого разбор режет на двоих.

Проверки: `npm run test:banned` (сверка по имени, id, feat. и фильтр списка)
и `npm run test:banned:ui` (кнопка на странице исполнителя, пункт в меню
трека, вкладка «Исполнители», пустой список в альбоме, чистый хвост AutoDJ,
перешагивание в очереди, разблокировка).

## Статистика прослушиваний

Отдельный экран `/stats` (пункт «Статистика» в медиатеке): сколько музыки
прошло за период, кто и когда звучал чаще всего.

**Где взять данные.** Subsonic-сервер «что я слушал» не отдаёт (scrobble —
только запись), поэтому всё считается из локальной истории
(`src/lib/playHistory.js`): трек попадает в неё, когда играл около 20 секунд.
Отсюда же экран «Недавнее».

**Что на экране**

* крупная цифра времени и четыре карточки: время, треки, исполнители, серия
  дней подряд;
* **активность по дням** — столбцы за 7 / 30 / 90 дней или за всё время;
* **топ исполнителей** с долями и **топ альбомов** с обложками (клик — переход,
  кнопка на карточке — проиграть);
* **когда вы слушаете** — тепловая карта «дни недели × часы»;
* **жанры** — по альбомам, с которых звучали треки (жанр в истории не пишется,
  поэтому альбомы запрашиваются у сервера, но не больше 14 штук и один раз);
* **мелочи**: рекордный день, любимое время, доля ночных прослушиваний, самый
  длинный трек;
* кнопка «Страница .html» — топ-20 отдельным файлом с вклеенными обложками.

**Как считается.** Вся арифметика — чистые функции `src/lib/stats.js`
(`buildStats`): границы периода, суммы, топы, сетка часов, серия дней.
Исполнители группируются по `artistId`, а если его нет — по имени, и подпись
берётся самая короткая («Sable & Sons», а не «Sable & Sons feat. Yeat»).
Жанры — единственное место, где нужен сервер.

**Демо-режим.** В демо библиотека пустая в смысле истории: статистику показать
не на чем, поэтому при первом подключении история один раз засеивается
правдоподобной выборкой (`src/lib/demoPlays.js`: любимые исполнители, вечерний
пик, плотные выходные, изредка тихие дни; зерно фиксировано — цифры не меняются
между запусками). Засев срабатывает только когда история пуста и помечается в
настройках (`demoPlaysSeeded`); при подключении к настоящему серверу засеянные
записи выбрасываются по метке времени, а реальные прослушивания — новее метки —
остаются.

Проверки: `npm run test:stats` (границы диапазона, сетка дней, тепловая карта,
топы, серия, формат времени, засев демо) и `npm run test:stats:ui` (засев в
демо, крупные цифры, столбцы, карта, переходы к исполнителю и альбому,
переключение промежутков, воспроизведение, пустая история, выброс демо-записей
при подключении к настоящему серверу).

## Случайный трек: анимация «Космос» (three.js)

Третий режим броска «случайный трек» (кроме пластинки и кубика) — **полёт сквозь
трёхмерный туннель обложек**: `src/lib/cosmosScene.js` (сцена) и
`src/components/RandomCosmos.jsx` (оверлей). Включается в «Настройки → Анимация
случайного трека → Космос 3D».

**Как это выглядит по фазам** (фазы те же, что у пластинки и кубика):

1. `idle` — камера дрейфует, обложки проявляются из тумана (задержка у каждой
   своя, поэтому туннель «наливается», а не включается разом)
2. `spin` — разгон: скорость летит с 6 до ~50 единиц в секунду, поле зрения
   раскрывается 62° → 74°, обложки вытягиваются по ходу полёта в световые
   полосы, камера слегка кренится (две волны разной частоты, чтобы движение
   не выглядело «по рельсу»)
3. `balance` — если сервер думает дольше 2,7 с, полёт замедляется до дрейфа:
   анимация не упирается в паузу и не выглядит зависшей
4. `settle` — впереди загорается портал с выпавшим треком, камера тормозит
   (критически задемпфированный подход, а не линейная интерполяция), а стены
   туннеля расходятся волной: у каждой обложки свой сдвиг, поэтому разлёт идёт
   не строем. Одновременно рассеивается туман — пространство «раскрывается»
5. `top` — обложка разворачивается к камере (`easeOutBack` с доводчиком),
   поле зрения сужается до 58° — геройский кадр, вокруг пульсирует кольцо и
   свечение цвета обложки, в этот момент монтируется скрытый плеер
6. `expand` — обложку подхватывает обычный `<img>` и по WAAPI летит точно
   в обложку полноэкранного плеера (shared element, как у пластинки)

**Техника**
- three.js грузится **динамическим импортом**: в основной бандл не попадает
  (отдельный чанк ~190 КБ в gzip) и не замедляет запуск. Когда режим выбран,
  чанк прогревается в простое (`prewarmThree` через `requestIdleCallback`),
  поэтому первый бросок не спотыкается о загрузку
- 54 обложки — процедурные текстуры на canvas (градиент, фигуры, зерно) с
  детерминированным генератором: от броска к броску туннель один и тот же, но
  смотрится как случайная подборка. Плюс 900 частиц пыли
- Материалы — `MeshBasicMaterial`: свет не нужен, вся глубина строится на тумане
  `FogExp2`, прозрачности и аддитивных подложках. Никаких пост-процессов и
  теней — сцена держится на любом железе
- Движение считается от **дельта-тайма** (`dt` с потолком 0,05 с): на 60 и на
  144 Гц анимация идёт с одной скоростью, а после фриза вкладки не «догоняет»
  рывком. Все сглаживания — экспоненциальные (`approach`), а не покадровые
- Обложки вне экрана переносятся вперёд по кругу — туннель бесконечный при
  фиксированном числе объектов
- При выходе всё освобождается: геометрии, материалы, текстуры, сам рендерер
- Плитки-порталы одеты в **настоящие обложки** фонотеки: тем же загрузчиком
  `src/lib/rollArt.js`, что и чёрная дыра, до 60 штук за бросок

**Запасной путь.** Без WebGL (отключённое аппаратное ускорение, старый драйвер)
или при потере контекста бросок **не ломается**, а продолжается плоской сценой
«пластинка» (`setDiceKind('vinyl')`) — пользователь просто видит другую
анимацию. Системная настройка «уменьшить движение» по-прежнему отключает
анимацию целиком: трек включается сразу.

- Проверка: `npm run test:cosmos:ui` (Playwright: сцена реально рисует — считаем
  draw-вызовы и кадры, фазы идут по очереди, обложка из портала улетает в плеер,
  без WebGL включается запасная сцена, в настройках есть переключатель)

## Из какой музыкальной папки трек

Плеер показывает, из какой музыкальной папки (библиотеки Navidrome) взят
текущий трек: метка с названием папки — в нижней панели под названием трека и
в полноэкранном плеере рядом с годом и форматом. Фонотеки часто ведут раздельно
(основная, винил, лайв-записи), а у трека это нигде не написано.

- **Клик по метке** ограничивает медиатеку этой папкой — то же, что выбрать её
  в шапке, но прямо от трека. Из полноэкранного плеера клик ещё и возвращает
  к библиотеке.
- **Когда папка одна**, метку не показываем: она не несёт информации и только
  занимает место.
- **Если папку узнать не удалось** (сеть оборвалась, сервер не отдаёт папки,
  альбом появился после перебора), метки просто нет. Музыка при этом играет как
  обычно — индекс необязательный.

**Почему это не берётся в лоб.** Subsonic не отдаёт номер музыкальной папки ни
в ответе о треке, ни в ответе об альбоме — только список самих папок
(`getMusicFolders`). Поэтому соответствие «альбом → папка» приложение собирает
само (`src/lib/folderIndex.js`): перебирает альбомы каждой папки по отдельности
(`getAlbumList2` с `musicFolderId`) и запоминает, где что лежит.

- Перебор идёт **в фоне** после подключения и не блокирует интерфейс: метка
  появляется, как только индекс готов
- Страницы по 500 альбомов, потолок 40 000 на папку — чтобы большой сервер не
  завалило запросами
- Индекс кэшируется в `localStorage` и привязан и к серверу, и к набору папок:
  переименовали папку или подключились к другому серверу — кэш выброшен и
  собран заново. Кэш пишется, только если альбомов не больше 15 000
- При одной папке на сервере перебирать альбомы незачем: любой трек и так из
  неё, это запоминается одной записью

- Проверка: `npm run test:folders:ui` (Playwright: индекс собран и альбомы
  действительно раскладываются по разным папкам, метка совпадает с папкой трека,
  меняется вместе с треком, клик ограничивает библиотеку, в низкой панели метка
  не вылезает за край, при одной папке её нет, после перезагрузки индекс берётся
  из кэша)

## Случайный трек: анимация «Чёрная дыра» (three.js)

Четвёртый режим броска — **чёрная дыра, которая выплёвывает обложки и засасывает
их обратно**: `src/lib/blackHoleScene.js` (сцена) и
`src/components/RandomBlackHole.jsx` (оверлей). Включается в «Настройки →
Анимация случайного трека → Чёрная дыра».

**Как это выглядит по фазам**

1. `idle` — горизонт «дышит», диск раскручивается, обложек ещё нет
2. `spin` — **выброс**: обложки вылетают из горизонта потоком (не залпом) и
   раскручиваются по спирали. Чем дальше от дыры, тем медленнее — как при
   разлёте от гравитации
3. `balance` — если сервер думает дольше 2,6 с, дыра **дышит**: поток плавно
   ходит от выброса к всасыванию и обратно (косинус, полный цикл ≈ 4,6 с).
   Проглоченные в этой фазе обложки не исчезают, а выплёвываются заново
4. `settle` — **разворот**: тот же поток меняет знак. Обложки тормозят,
   разворачиваются и падают внутрь, разгоняясь и вытягиваясь в нити
5. `top` — когда всё съедено, из горизонта поднимается обложка выпавшего трека,
   разворачиваясь к зрителю; дыра за ней разгорается акцентным цветом
6. `expand` — обложку подхватывает обычный `<img>` и по WAAPI летит точно
   в обложку полноэкранного плеера (shared element, как в остальных режимах)

**Главное в устройстве.** Выброс и всасывание — не два эффекта, а один
параметр `flow` от +1 до −1. Он меняется плавно, поэтому обложки не
«переключаются», а именно разворачиваются: гасят скорость, проходят через ноль
и летят назад. Окончательным всасывание становится только в `settle` — там
обложка, дойдя до горизонта, пропадает навсегда.

**Мелочи, из которых складывается правдоподобность**
- угловая скорость по Кеплеру: `ω ∝ r^-1.5` — внутренние обложки несутся
  быстрее внешних, поэтому облако закручивается в спираль
- выброс гасится к краю (`0.35 + 1.5/r`), всасывание разгоняется к центру
  (`0.55 + 0.42·r`) — физически ровно наоборот, и это читается как притяжение
- у горизонта обложку вытягивает в нить: масштаб считается по касательной,
  которую мы проецируем на экран, — нить всегда идёт вдоль её пути в кадре
- обложки развёрнуты к камере (иначе арт не прочитать), но вращаются в своей
  плоскости — и не выглядят наклейками
- горизонт — невидимая сфера, которая пишет только глубину: она прячет
  обложки, оказавшиеся за дырой, а чёрное внутри тени рисует шейдер
- всё считается от дельта-тайма: на 60 и 144 Гц анимация идёт с одной скоростью

**Сама дыра считается, а не нарисована.** `src/lib/holeShader.js` — это
фрагментный шейдер на весь кадр: из камеры в сцену пускается луч, и его путь
интегрируется по уравнению нулевой геодезики в метрике Шварцшильда
(в единицах радиуса Шварцшильда rs = 1):

```
d²x/dλ² = −1.5 · h² · x / r⁵ ,   h = |x × v|      // схема «скорость Верле»
```

Никаких нарисованных дуг и «чёрного круга с размытым кольцом». Все эффекты,
которые раньше приходилось подделывать, получаются сами:

- **тень** — луч либо уходит за горизонт, либо нет. Её радиус выходит ровно
  `3√3/2 · rs` — критический прицельный параметр, а не подогнанное число
- **линзирование** — луч уносит на бесконечность весь накопленный изгиб,
  поэтому небо вокруг дыры закольцовано само, а диск виден и снизу, и сверху:
  свет огибает дыру. За пределами проинтегрированного участка остаточный
  изгиб добирается слабополевым рядом — так дешевле, а ошибка не видна
- **кольцо Эйнштейна** — тонкая нить света ровно на критическом прицельном
  параметре; её, как и положено, гасит передний край диска
- **релятивистские джеты** — два луча вдоль оси вращения диска. Это объёмная
  среда, поэтому она считается тем же маршем: сколько вещества луч прошёл на
  шаге, столько и посветило. Узлы в струе бегут наружу, а струя, летящая
  на наблюдателя, светит заметно ярче уходящей — тот же доплеровский фактор

**Аккреционный диск — настоящий.** Тонкий, от ISCO (3 rs) наружу:

- профиль температуры Shakura–Sunyaev (`T ∝ r^-3/4`), цвет — планковского
  излучателя по этой температуре: от багрового края к бело-голубому
- **релятивистский набор**: вещество летит по Кеплеру со скоростью
  `v = √(GM/r)` (в долях c), доплеровский фактор `1/(γ(1 − β·n))` складывается
  с гравитационным красным смещением `√(1 − rs/r)` в один множитель `g`;
  яркость растёт как `g³·⁴` (инвариант `I_ν/ν³`), а цвет сдвигается по
  температуре. Поэтому набегающий край диска светит в разы ярче уходящего и
  уходит в бело-голубое, а уходящий багровеет — та самая асимметрия, по
  которой кадр из «Интерстеллара» узнают с первого взгляда
- узор закручивается по Кеплеру (`ω ∝ r^-1.5`): внутренние слои обгоняют
  внешние, и потоки вытягиваются вдоль орбиты. Шум берётся в полярных
  координатах на окружности — разрез по азимуту получается бесшовным
- **диск живой**: три масштаба шума (сгустки, потоки, нити), «рёбра» вместо
  пятен — из облака получаются вытянутые жгуты; редкие яркие сгустки
  (`pow(n, 3.2)`) вращаются вместе с потоком; раскалённая кромка на внутреннем
  крае; вещество видимо стекает внутрь, а внутренняя область ещё и пульсирует
- **камера не стоит**: наклон к плоскости диска дышит (диск то виден почти
  с ребра, то слегка раскрывается), поверх — медленный крен

**Точность проверена численно** (прогон той же схемы интегрирования в Node):
в слабом поле отклонение сходится к ряду `2rs/b + 2,945(rs/b)² + 5,33(rs/b)³` —
расхождение 0,00 % при b = 50 rs и 0,35 % при b = 12 rs; критический
прицельный параметр выходит между 2,59 и 2,60 rs при теоретических 2,5981.

**Настоящие обложки.** Из дыры вылетают не абстрактные квадраты, а обложки из
вашей фонотеки. `src/state/store.js` вместе с броском публикует `dice.pool` — id
до 40 треков-кандидатов, а `src/lib/rollArt.js` раскачивает их по кэшу
(`peekCover(id, 300)` сначала, затем `resolveCover`) в пять параллельных дорожек.
Размер запрошен намеренно тот же, что в списках (300), поэтому картинки
попадаются в горячий кэш и прилетают за миллисекунды. В сцене пул держит до 44
текстур (`MAX_POOL`): пока летят первые обложки, в него подложены 8 процедурных
заготовок, но каждая пришедшая настоящая вытесняет одну из них — в установившемся
броске процедурных не остаётся вовсе. «Космос 3D» получает те же обложки тем же
загрузчиком: его плитки-порталы тоже одеты в реальный арт.

**Постобработка: свет, которого не бывает в лоб.**
Линзирование и кольцо Эйнштейна считает сама дыра, поэтому
`src/lib/threePost.js` остаётся за свечение и за оптику: он забирает сцену
в полуэкранный набор таргетов и собирает картинку заново:

1. **порог** — ярче `threshold` уходит в свечение, с мягким коленом, а не обрезкой
2. **размытие** — два прохода разделяемого гауссиана (радиусы 1 и 2.6) на половине
   разрешения: широкое гало без лишней стоимости
3. **остатки гравитации** — совсем небольшой изгиб экрана
   (`strength · holeR² / b`): он больше нужен обложкам, чем фону, — у горизонта
   их слегка ведёт, как настоящий свет
4. **хроматическая аберрация** — каналы расходятся на ±2 % к краю
5. **тонмап ACES** — аккуратно саживает пересветы диска и обложек
6. **киноплёнка** — тени уходят в холодный, света в тёплый, поверх лёгкая
   S-кривая по контрасту: без этого кадр читается «картинкой», а не снятым
   материалом

Сцена рисуется в `HalfFloatType`-цель с 4× MSAA, поэтому свет диска не «ступеньками».
Сверху постобработки, поверх `clearDepth()`, рисуется отдельный кадр с обложкой
выпавшего трека: она остаётся резкой, и DOM-элемент подхватывает её уже без
искажений. Вспышки при выбросе и при поглощении — аддитивные квады в цвете
акцента; их яркость подмешана в `boost` bloom'а, так что дыра светится сильнее
именно в моменты, когда что-то глотает.

**Производительность и запасной путь.** Геометрии в сцене почти нет — пара
сотен вызовов не наберётся, вся картинка считается шейдером, и считается от
дельта-тайма: на 60 и 144 Гц анимация идёт с одной скоростью. Стоимость кадра
целиком зависит от числа шагов интегрирования, поэтому качество подстраивается
по факту: считается средняя длительность последних кадров, сначала урезаются
шаги (160 → 64), потом, если и это не помогло, разрешение (до 0.5 от
`devicePixelRatio`, который сам ограничен 1.6). Слабая машина получит дыру
чуть грубее, но без просадок; сильная — полные 160 шагов. Есть и ручная
установка (`scene.setQuality`) — ей пользуются прогоны на CPU.

three.js, как и в «Космосе», грузится отдельным чанком и прогревается в простое.
Без WebGL или при потере контекста бросок продолжается плоской сценой
«пластинка»; системное «уменьшить движение» отключает анимацию целиком.

- Проверка: `npm run test:blackhole:ui` (Playwright: сцена реально рисует,
  обложки вылетают, поток разворачивается и проходит через ноль, дыра их
  проглатывает, обложка из горизонта улетает в плеер; отдельно — что в ожидании
  дыра дышит в обе стороны, что без WebGL включается запасная сцена и что
  переключатель из пяти режимов помещается в окно настроек)
- Качество проверяется не на глаз: `tools/png.mjs` разбирает PNG снимка без
  зависимостей и считает яркость и контраст. Тест требует, чтобы кадр был и не
  пустым, и не плоским (среднее > 6 при СКО > 12), и чтобы **центр кадра был
  заметно ярче краёв** — то есть дыра со светящимся кольцом действительно
  остаётся смысловым центром, а не тонет в равномерном фоне. Плюс отдельная
  проверка, что в сцену попало > 0 настоящих обложек (`stats().art`)
- Прогоны, где время сцены ведут вручную, работают на урезанном качестве
  (`setQuality({ steps: 48, scale: 0.5 })`): в headless WebGL считает
  SwiftShader на паре ядер, и полная картинка просто не успевала бы за
  таймерами фаз. Раздел со снимками качество не трогает — только разрешение

## Подключение к Navidrome

При первом запуске введите:

- **Адрес сервера** — например `http://localhost:4533` или `https://music.example.com`
  (без `/rest`, без слэша в конце);
- **Пользователь** и **пароль** от Navidrome.

Аутентификация — стандартная схема Subsonic: на каждый запрос генерируется случайная соль
и `token = MD5(пароль + соль)`, сам пароль по сети не передаётся. Учётные данные хранятся
локально в `config.json` внутри `userData` приложения.

CORS: Navidrome не отдаёт `Access-Control-Allow-Origin` для произвольных источников,
поэтому в главном процессе Electron заголовки ответов патчатся через
`session.webRequest.onHeadersReceived`. Это нужно и для эквалайзера — Web Audio требует
CORS-совместимый источник, иначе граф обработки не подключить.

Кнопка **«Посмотреть демо-библиотеку»** на экране входа поднимает локальный мок
(12 исполнителей, ~30 альбомов, плейлисты, синхронный текст, распределённый по длительности трека) —
удобно, чтобы оценить интерфейс без сервера. В демо за текстом на lrclib.net клиент сам не ходит:
кнопка «Искать на LRCLIB» на вкладке «Текст» включает внешний поиск вручную. Реального звука в демо нет: прогресс проигрывается виртуальным таймером.

## Совместимость

Работает с любым сервером Subsonic API 1.16.1+, но рассчитан на Navidrome
(OpenSubsonic-расширения: структурированные тексты, `getTopSongs`, `getArtistInfo2`).
Функции, которых нет на сервере, деградируют мягко — интерфейс не ломается.

Spotidrome не связан со Spotify AB; сходство ограничено визуальным стилем интерфейса.
