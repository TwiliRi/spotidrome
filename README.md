# 🎧 Spotidrome

Десктоп-клиент для **Navidrome** (Subsonic / OpenSubsonic API), максимально похожий на Spotify:
тёмная тема, зелёный акцент, боковая медиатека, крупные обложки-hero с динамическим градиентом,
нижний плеер, очередь справа и полноэкранный режим «Сейчас играет» с синхронным текстом.

![Spotidrome](assets/icon.png)

## Управление треком снаружи окна

Чтобы не открывать приложение ради «дальше / пауза / назад», управление
вынесено в системные элементы. Состояние плеера renderer отдаёт в main по IPC
(`player:state`), команды приходят обратно по каналу `media-key`
(`electron/mediaControls.cjs`).

- **Windows** — кнопки на превью в панели задач (thumbnail toolbar): наведите
  курсор на значок Spotidrome, и под миниатюрой окна появятся, как в Spotify,
  пять кнопок: ♥ / 👎 / ◀◀ / ▶❚❚ / ▶▶ — «в любимые», «больше не играть»,
  назад, пауза-пуск, вперёд. Сердце показывает текущее состояние: контур —
  трека нет в любимых, зелёное залитое — уже добавлен. Палец вниз так же:
  контур — обычный трек, залитый красный — трек в исключённых. Нажатие
  переключает; дизлайк заодно выкидывает трек из очереди и включает
  следующий. Больше семи кнопок Windows не принимает — запас есть. Там же подсказка с названием
  трека, бейдж «играет/пауза» поверх значка и полоса прогресса по значку.
- **Linux** — MPRIS (D-Bus): контролы появляются в медиа-виджете GNOME/KDE, в
  апплетах громкости, на медиаклавишах и в панелях, умеющих MPRIS-превью;
  прогресс по значку работает в Unity-совместимых панелях. Обложка отдаётся из
  дискового кэша (`userData/covers`).
- **macOS** — меню в доке (правый клик по значку).
- **Везде** — иконка в трее: подсказка с текущим треком и меню
  «Предыдущий / Пауза / Следующий / В любимые / Больше не играть / Показать /
  Выход» (два последних пункта — с галочкой текущего состояния), клик по
  значку прячет и показывает окно. Те же пункты продублированы в меню дока
  на macOS.

**Почему кнопок может не быть и как это чинится.** Windows принимает кнопки
превью (`ThumbBarAddButtons`) только у окна, которое уже показано и имеет
кнопку в панели задач. Наше окно создаётся скрытым (`show: false`, показ по
`ready-to-show`), поэтому ранний вызов молча проваливался — а Electron после
него считал кнопки «уже добавленными» и дальше слал `ThumbBarUpdateButtons` в
пустоту: кнопки не появлялись до конца сессии. Теперь регистрация идёт только
после события `show`, результат вызова проверяется, при отказе делается до 12
повторов с нарастающей паузой, а на `show` / `restore` / `focus` кнопки
перерегистрируются (например, после перезапуска `explorer.exe`). Плюс задан
`app.setAppUserModelId('app.spotidrome.desktop')` — без него Windows иногда не
связывает окно с кнопкой в панели задач.

Проверить состояние можно в «О программе» → «Управление снаружи окна»:
там видно, приняла ли система кнопки («включены» / «ждём»), есть ли значок в
трее и работает ли MPRIS. В консоли main-процесса при успехе печатается
`[taskbar] кнопки на превью окна зарегистрированы`.

Кнопки автоматически гаснут, когда действие недоступно (нет очереди, нет
предыдущего трека, ничего не играет). Если в системе нет D-Bus или области уведомлений, всё
молча деградирует — приложение продолжает работать.

Реализация: `electron/mediaControls.cjs` (панель задач, трей, док, MPRIS),
`electron/mediaIcons.cjs` (иконки вшиты как data URL, чтобы работать внутри
`app.asar`), `src/lib/desktopMedia.js` (отдаёт состояние, не чаще раза в
секунду). MPRIS подключён как **опциональная** зависимость `mpris-service`.


## Сборка под Linux

Собирается и проверено на Debian 13 / Node 20 (electron-builder 25, Electron 32):

```bash
npm install
npm run dist:linux     # vite build + electron-builder --linux AppImage deb tar.gz
```

Готовые артефакты складываются в `release/`:

| Файл | Размер | Как запускать |
|---|---|---|
| `Spotidrome-1.0.0.AppImage` | ~108 МБ | `chmod +x` и запустить (нужен FUSE; иначе `--appimage-extract-and-run`) |
| `spotidrome_1.0.0_amd64.deb` | ~74 МБ | `sudo apt install ./spotidrome_1.0.0_amd64.deb` |
| `spotidrome-1.0.0.tar.gz` | ~101 МБ | распаковать и запустить `./spotidrome` |
| `release/linux-unpacked/` | ~280 МБ | распакованная сборка для отладки |

Зависимости `.deb` (ставятся автоматически): `libgtk-3-0, libnotify4, libnss3,
libxss1, libxtst6, xdg-utils, libatspi2.0-0, libuuid1, libsecret-1-0`.
Пакет кладёт приложение в `/opt/Spotidrome`, ярлык в
`/usr/share/applications/spotidrome.desktop` и иконку в `hicolor`.

Полезно знать:
- сборка **кросс-платформенная только частично**: с Linux нормально собираются
  Linux-цели, для Windows нужен Wine, для macOS — сама macOS;
- `.deb`/`.rpm` требуют заполненных `author.email`, `homepage` и
  `build.linux.maintainer` в `package.json` — без них electron-builder падает;
- ARM: `npm run dist:linux -- --arm64` (или `--armv7l`);
- сборка тянет ~110 МБ бинарей Electron в `~/.cache/electron*`, первый прогон
  дольше остальных.


## NixOS: запуск и сборка

На NixOS обычный `npm install && npm run dist:linux` ломается: в системе нет FHS,
и скачанные npm-бинарники (`electron`, `app-builder-bin`, `esbuild`, `mksquashfs`
из appimagetool, `ruby` внутри `fpm`) не находят `/lib64/ld-linux-x86-64.so.2`
и системные `.so`. В репозитории лежит всё, чтобы это обойти:

| Файл | Зачем |
|---|---|
| `shell.nix` | `nix-shell`, `nix-shell -A fhs`, `nix-build -A app` |
| `flake.nix` | `nix develop`, `nix build .#spotidrome`, `nix run .#fhs` |
| `nix/shells.nix` | dev-окружение и FHS-окружение (список библиотек) |
| `nix/package.nix` | `buildNpmPackage`: настоящий пакет с ярлыком и иконкой |

### 1. Разработка — Electron из nixpkgs

```bash
nix-shell            # либо: nix develop
npm install          # ELECTRON_SKIP_BINARY_DOWNLOAD=1 уже выставлен
npm run start:nix    # Vite + Electron (переменная $ELECTRON_BIN)
```

Окружение даёт Node 22 (`nodejs_20` из nixpkgs выпилен — EOL 30.04.2026), Python 3
и Electron из nixpkgs, а также переменные:

- `ELECTRON_SKIP_BINARY_DOWNLOAD=1` — npm не тянет свой бинарник, он всё равно не запустится;
- `ELECTRON_OVERRIDE_DIST_PATH` — распакованный Electron для electron-builder;
- `ELECTRON_BIN` — путь к запускаемому Electron, его использует `npm run start:nix`.

Только фронтенд (`npm run dev`, http://localhost:5173) работает и без всего этого.

### 2. Установщики (AppImage / deb / tar.gz) — FHS-окружение

`buildFHSEnv` создаёт внутри chroot привычные `/usr/lib` и `/lib64`, поэтому
electron-builder и его скачанные утилиты работают как на Ubuntu:

```bash
# интерактивно
nix-shell -A fhs                 # либо: nix develop .#fhs
npm install && npm run dist:linux

# одной командой (у nix-shell --run с FHS команда игнорируется — это нормально)
nix run .#fhs -- -c "npm install && npm run dist:linux"
```

Проверено на месте: получаются `Spotidrome-1.0.0.AppImage` (108 МБ),
`spotidrome_1.0.0_amd64.deb` (74 МБ) и `spotidrome-1.0.0.tar.gz` (102 МБ).
В `targetPkgs` пришлось добавить неочевидное — если правите список, не выкидывайте:

| Пакет | Без него падает |
|---|---|
| `zlib`, `xz`, `lz4`, `zstd`, `bzip2` | `mksquashfs: libz.so.1: cannot open shared object file` при сборке AppImage |
| `libxcrypt-legacy` | `ruby` внутри `fpm`: `libcrypt.so.1: cannot open shared object file` при сборке `.deb` |
| `binutils` | `fpm`: `Need executable 'ar' to convert dir to deb` |
| `fuse` | запуск получившегося AppImage |

### 3. Настоящий пакет Nix — `nix build`

```bash
nix build .#spotidrome        # либо: nix-build -A app
./result/bin/spotidrome
```

`nix/package.nix` — это `buildNpmPackage`: `npm ci` из `package-lock.json`,
`vite build`, затем `npm prune --omit=dev`, а сверху `makeWrapper` над
`${electron}/bin/electron` с путём к приложению. В результат попадают
`bin/spotidrome`, `share/applications/spotidrome.desktop` (с
`StartupWMClass=Spotidrome`, чтобы значок в доке не двоился) и иконка в `hicolor`.
Сам каталог приложения ~16 МБ: Electron берётся из nixpkgs, а не копируется внутрь.

Установить в систему:

```nix
# configuration.nix
environment.systemPackages = [ inputs.spotidrome.packages.${pkgs.system}.spotidrome ];
```

Два момента:

- **`npmDepsHash`** в `nix/package.nix` привязан к `package-lock.json`. После любого
  изменения зависимостей подставьте `lib.fakeHash`, запустите сборку и скопируйте
  правильный хеш из текста ошибки (`specified: … got: …`).
- Каталог лучше держать под git (`git init && git add -A`): иначе flake копирует в
  store весь каталог целиком, вместе с `node_modules` и `release`.

### Версия Electron

В nixpkgs-unstable сейчас `electron-43.4.1`, приложение писалось под 32.3.3 —
API, которое используется (thumbar, tray, MPRIS через `mpris-service`, `cover://`),
совместимо. Если нужна ровно ветка 32.x, запиньте старый nixpkgs и разрешите
устаревший пакет:

```nix
nixpkgs.config.permittedInsecurePackages = [ "electron-32.3.3" ];
```

### Чужой AppImage на NixOS

Если вы скачали `Spotidrome-1.0.0.AppImage` (собранный где-то ещё), запускать так:

```bash
nix-shell -p appimage-run --run "appimage-run Spotidrome-1.0.0.AppImage"
# или системно:
#   programs.appimage.enable = true;
#   programs.appimage.binfmt = true;
```

### Альтернатива FHS — `nix-ld`

Чтобы обычные скачанные бинарники (в том числе `node_modules/electron`) работали
без chroot:

```nix
programs.nix-ld.enable = true;
programs.nix-ld.libraries = with pkgs; [
  alsa-lib at-spi2-atk at-spi2-core atk cairo cups dbus expat gdk-pixbuf glib gtk3
  libdrm libnotify libsecret libxkbcommon libgbm nspr nss pango udev
  xorg.libX11 xorg.libXcomposite xorg.libXdamage xorg.libXext xorg.libXfixes
  xorg.libXrandr xorg.libXtst xorg.libxcb xorg.libxshmfence
];
```

### Мелочи NixOS

- **Трей** в GNOME виден только с расширением AppIndicator (`gnomeExtensions.appindicator`);
  в KDE/XFCE/Waybar работает из коробки.
- **MPRIS** (кнопки на клавиатуре, виджеты плеера) требует сессионного D-Bus — в
  обычной графической сессии он есть, в `nix-shell` по SSH его может не быть, тогда
  Spotidrome просто молча пропускает MPRIS.
- Если Electron ругается на песочницу (`SUID sandbox helper`), запускайте
  `spotidrome --no-sandbox` — в пакете из nixpkgs это уже учтено.


## Возможности

**Несколько исполнителей у трека**
- Имена в списке треков, в плеере, в панели очереди и на полноэкранном экране
  кликаются **по отдельности**: «Yeat & Summrs» — две разные ссылки, разделитель
  («&», «feat.», запятая) остаётся обычным текстом и не подсвечивается
- Источник данных — OpenSubsonic-поля `artists` / `albumArtists` /
  `participants.artist` (их отдаёт Navidrome). Тогда подпись даже не приходится
  разбирать: имена берутся готовыми, а исходное написание сохраняется
- Если сервер их не прислал, подпись разбирается в три шага:
  1. знаки препинания — `, ; / | · •` (внутри имён почти не встречаются);
  2. явное участие — `feat.` `ft.` `featuring` `with` `vs`;
  3. спорные — `&` `+` `×` `x` `и` `and`: по ним режем, **только если** такого
     исполнителя целиком нет в библиотеке. Поэтому «Yeat & Summrs» превращается
     в две ссылки, а «Sable & Sons» остаётся одной — проверка идёт по имени
     исполнителя из `artistId` и поиском `search3`
- `artistId` трека **не раздаётся** первому имени: Navidrome кладёт туда
  исполнителя альбома, который может стоять в подписи вторым (именно из-за этого
  «Yeat & Summrs» раньше вело на Summrs). Каждое имя ищется отдельно, результаты
  кэшируются на сессию, ненайденное имя открывает поиск
- В контекстном меню трека вместо одного пункта появляется список «Перейти
  к исполнителю → …», и «Радио: …» строится по каждому участнику отдельно
- На вкладке «Об исполнителе» (полноэкранный плеер) сверху появляются чипы —
  переключение между участниками трека без ухода со страницы
- Подчёркивается **только имя под курсором**: старое правило
  `.t-artist:hover { text-decoration: underline }` подсвечивало всю ячейку, из-за
  чего четыре ссылки выглядели одной. Разделители некликабельны (`pointer-events: none`)
- Проверено на подписях `Quality Control feat. Quavo, Offset & Lil Yachty`,
  `Yeat & Summrs`, `Summrs, Sable & Sons`, `Sable & Sons feat. Yeat`, `A feat. B`
  и `A, B` — все они есть в демо-библиотеке

**Громкость**
- Шкала логарифмическая: положение ползунка возводится в степень 2.25, поэтому
  50% — это примерно −13 дБ, а не «почти максимум». Внизу шкалы наконец есть
  запас для тихой настройки
- Значение применяется **на лету**, пока тянете ползунок (раньше — только после
  отпускания); частота обновления привязана к кадрам, а на диск настройка
  сохраняется один раз, через 350 мс после последнего движения
- Колесо мыши над ползунком меняет громкость шагами по 4%, при наведении и
  перетаскивании показывается подсказка с процентами
- Перемотка по-прежнему срабатывает только при отпускании — поток не дёргается

**Оболочка окна**
- Кастомный тайтл-бар в духе актуального Spotify: окно без системной рамки
  (`frame: false`, на macOS — `hiddenInset` со сдвинутым «светофором»)
- Глобальная навигация в шапке: логотип, стрелки назад/вперёд, круглая кнопка «Главная»,
  крупное поле поиска по центру (`Ctrl/Cmd + K`, `L` или `/`), эквалайзер и меню аккаунта справа
- Свои кнопки свернуть / развернуть / закрыть на Windows и Linux, перетаскивание окна за шапку,
  двойной клик разворачивает, шапка приглушается когда окно не в фокусе
- При прокрутке страницы в контентной области проявляется липкая полоса с названием
  и компактной зелёной кнопкой воспроизведения

**Кэш обложек**
- URL картинок и стримов теперь стабильны: соль Subsonic-авторизации одна на сессию,
  поэтому работают и HTTP-кэш браузера, и наш кэш (раньше каждый рендер давал новый адрес)
- Три уровня: LRU в памяти (500 записей) → диск/Cache Storage → сеть
- В десктопе картинки лежат в `userData/covers` и отдаются по схеме `cover://`
  с `immutable`-заголовком; размер кэша ничем не ограничен — чистится только вручную
  кнопкой «Очистить» в настройках
- В браузере используется Cache Storage `spotidrome-covers-v1` + blob-URL
- Обложки ближайших 8 треков очереди подгружаются заранее — переключение без мигания
- Размер кэша и кнопка «Очистить» — в окне «Настройки»
- Если кэш почему-то не отдаёт картинку, клиент автоматически откатывается на прямой
  URL сервера: `<img>` перезапрашивает обложку и запись кэша инвалидируется,
  а неработающий `cover://` отключается на всю сессию после первой же проверки

**AutoDJ — бесконечная очередь**
- Тумблер в панели очереди, кнопка-антенна в плеере и клавиша `D`
- Когда впереди остаётся меньше N треков (3/5/10/20), клиент сам дописывает подходящие;
  очередь при этом не заканчивается — `next()` дозаправляет её на лету
- Режимы подбора: **Микс** (похожие + жанр + случайные), **Похожие** (`getSimilarSongs2`,
  с запасным вариантом через `getArtistInfo2` → `getTopSongs` близких артистов),
  **Исполнитель**, **Жанр**, **Любимое**, **Случайно**
- «Не повторять недавнее» помнит последние 500 автотреков; подбор не залипает
  на одном исполнителе (не больше половины порции)
- Автотреки помечены зелёной полоской и значком антенны; при выключении AutoDJ
  неигранный автохвост убирается, при смене режима — пересобирается
- «Радио»: в контекстном меню трека — «Радио по треку» и «Радио: исполнитель»,
  на странице артиста — кнопка «Радио». Запускает затравку и включает AutoDJ
- Настройки продублированы в окне «Настройки» и сохраняются между запусками

**Случайный трек — анимация «ставим пластинку»**

Сцена рисуется на canvas 2D (`src/lib/vinylScene.js`, компонент
`src/components/RandomVinyl.jsx`), фазы приходят из стора и привязаны к реальной
загрузке, а не к таймерам. Всё считается на `requestAnimationFrame` с
дельта-таймом, текстуры (дорожки винила, этикетка) генерируются процедурно
под текущий размер окна и DPR.

1. `idle` (700 мс) — пластинка падает на диск вертушки, тень под ней уплотняется
2. `spin` — раскрутка и вращение с «детонацией» (wow&flutter), анизотропный блик
   винила, пыль в луче света. Длится **ровно столько, сколько грузится трек**
   (минимум 1.4 с)
3. `balance` — если ответа нет дольше 2.6 с, тонарм зависает над краем и «ищет
   дорожку», подпись меняется на «Ищем дорожку…»
4. `settle` (900 мс) — тонарм по честной кинематике поворотного тонарма
   (угол считается теоремой косинусов, игла всегда точно на дорожке)
   опускается, в момент касания — вспышка и кольцевые волны по пластинке
5. `top` — камера наезжает на этикетку, пластинка останавливается и доворачивается
   ровно, бумажная этикетка кроссфейдом превращается в обложку трека
6. `expand` — круглую обложку подхватывает `<img>` и по WAAPI перелетает в
   обложку плеера, попутно превращаясь из круга в квадрат со скруглением

## Тексты песен: Navidrome + LRCLIB

Тексты собираются из двух источников (`src/lib/api.js` → `getLyrics`, вся сетевая часть — в `src/lib/lyrics.js`):

1. **Сервер.** `getLyricsBySongId` (OpenSubsonic) — структурированные строки с таймкодами из
   тегов трека или `.lrc` рядом с файлом; если их нет, старый `getLyrics?artist=&title=` — текст без таймкодов.
2. **LRCLIB** (`https://lrclib.net/api/get`, затем `https://lrclib.net/api/search`) — открытая база
   синхронизированных текстов без ключей и регистрации. Отвечает, когда на сервере текста нет вообще,
   и дописывает тайминг к несинхронному тексту из тегов (если слова совпадают).

Порядок и правила:

- свой **синхронный** текст с сервера всегда в приоритете — LRCLIB для такого трека не дёргается;
- запрос к LRCLIB идёт с названием и артистом, очищенными от «(Official Video)», «[Lyrics]»,
  «- 2011 Remaster», «feat. …»: точный `get` с альбомом и длительностью → `get` без них → `search`
  с выбором лучшего варианта (свой рейтинг: есть синхронизация, близость названия/артиста, разница длительности);
- **инструменталы** не выдумываются: если LRCLIB отвечает `instrumental`, так и пишется — «Инструментал»;
- ответы (и «не нашли тоже») кэшируются в `localStorage` на 80 треков, пустые — с протуханием за 4 дня;
- у LRCLIB вежливый лимит: **не чаще одного запроса в секунду**, очередь общая для всех треков,
  ответы `429`/`503` (`server busy`) повторяются один раз с паузой по `Retry-After`.

Интерфейс (вкладка «Текст» в полноэкранном плеере, клавиша `F`):

- активная строка белая, прошлые гаснут, будущие размыты; клик по строке перематывает;
- если в тексте есть метки слов (`<мм:сс.мс>` — расширенный LRC), подсвечиваются и сами слова;
- `−` / `+` сдвигают текст на 0.5 с (до ±30 с) — лечит треки с «тихим» началом или ремастер-сдвиг;
  значение видно в шапке, сброс — кликом по нему. Правка живёт в настройках и не требует нового запроса;
- в шапке — источник (`сервер` / `LRCLIB` / `демо`), ссылка на страницу текста и кнопка
  «найти заново» (обходит кэш; в демо-режиме это единственный способ увидеть работу LRCLIB).

Настройки (шестерёнка → «Тексты»):

| Переключатель | По умолчанию | Что делает |
|---|---|---|
| Тексты: база LRCLIB | включено | искать недостающие тексты в `lrclib.net` |
| Готовить тексты заранее | включено | при старте трека подтягивать тексты для следующих 3 треков очереди — текст готов до переключения |
| Поправка синхронизации | 0 с | глобальный сдвиг таймкодов; там же кнопка «Кэш» — сбросить кэш текстов |

## Что подправил сплошной аудит

Полный проход по кодовой базе (10,5 тыс. строк) — исправлены реальные дефекты,
каждый закрыт проверкой в `tools/test-audit.mjs` или `tools/e2e-audit.mjs`:

* **Удаление трека из плейлиста.** Индекс брался от видимой строки таблицы; если
  выше стоял исключённый (скрытый) трек, удалялся сосед сверху. Теперь трек
  ищется по `id` в исходном списке плейлиста.
* **Ошибки сервера при правке плейлиста.** `updatePlaylist` не смотрел на ответ и
  «успешно» добавлял треки в чужой или удалённый плейлист; теперь статус
  `subsonic-response` проверяется, а текст ошибки уходит в уведомление.
* **Зависание без ответа.** Запросы к серверу получили таймаут 20 с — раньше
  «проверка доступа» могла висеть бесконечно.
* **Эквалайзер.** Предусиление оставалось в тракте при выключенном эквалайзере
  (звук становился громче); при пересоздании аудио-графа полосы терялись.
  Теперь фильтры помнят последние значения и возвращают их при включении.
* **Очередь.** Удаление играющего трека из очереди останавливало звук — теперь
  включается следующий. Защита от исключённых треков в `next()` перечитывает
  очередь (AutoDJ успевал её дополнить).
* **Форматирование.** Длительность больше часа показывалась как `75:32`, размеры
  от 1 ТБ — как `undefined`, «59.7 мин» округлялось до «1 ч 60 мин».
* **Офлайн.** Лишние перечитания списка исключённых при скачивании могли стереть
  дизлайки из памяти; пустой или оборванный файл больше не считается скачанным;
  скачивание альбома выдаёт одно уведомление, а не по одному на трек.
* **Биографии исполнителей** приходили HTML'ом и вставлялись в DOM как есть —
  теперь это текст: теги вырезаются, `onerror`/`javascript:` невозможны.
* **Мелочи.** Клик по обложке в нижнем плеере не открывал полноэкранный режим
  (`onClick` терялся), страница жанра падала на `%` в адресе, альбом и плейлист
  крутили бесконечный спиннер при ошибке загрузки, слушатель `scroll` у
  контекстного меню копился, цвет обложки пересчитывался на каждой странице,
  колесо мыши над ползунком громкости ещё и прокручивало список.
* **Сохранение настроек** записывалось с задержкой 350 мс и терялось при быстром
  закрытии окна — добавлен сброс на `pagehide`/скрытии вкладки.
* **Электрон.** Имя офлайн-файла строилось из `id` трека без очистки (выход за
  папку кэша), редиректы скачивания не считались, а оборванная загрузка оставляла
  `.part`. Проверка схемы, лимит редиректов, удаление мусора.
* **Производительность.** Почти все компоненты подписывались на весь стор, поэтому
  отмечка времени проигрывания (4 раза в секунду) перерисовывала медиатеку,
  очередь, список треков и поле ввода поиска. Подписки стали точечными.
* **Разработка.** Политика безопасности в `index.html` блокировала HMR-сокет Vite;
  в дев-режиме `ws:`/`wss:` разрешены через `.env.development`, в сборке политика
  остаётся строгой.

## Виртуальные списки и «Недавнее»

**Виртуализация списков (`react-window`)**
- Порог — 60 строк (`VIRTUAL_FROM` в `src/components/TrackList.jsx`): короче —
  обычный рендер, ничего не меняется; длиннее — список собирается заново
- В большом плейлисте раньше в DOM жило до 100 тыс. узлов: 4000 строк × ~25 элементов.
  Теперь в DOM только видимые строки плюс запас (`overscanCount`), а `scrollHeight`
  равен полной высоте списка, поэтому полоса прокрутки честная
- `rowHeight` — не магическое число, а `row` из `DENSITY` (`src/lib/uiLayout.js`),
  из той же таблицы, что и CSS-переменная `--row-h`: компактный/обычный/просторный
  режимы и ползунок масштаба не разъезжаются со списком
- У `react-window` v2 нет привязки к чужому скролл-контейнеру (в отличие от
  `WindowScroller` из react-virtualized), поэтому у списка **свой** скроллбокс:
  высота считается до низа окна (`VList.jsx`), а при прокрутке страницы —
  пересчитывается, так что список занимает место уехавшего вверх героя
- Заголовок списка в виртуальном режиме перестаёт быть `sticky` (он и так над
  списком), а при заходе в огромный список сразу прокручивается к играющему
  треку (`scrollToRow`)
- Проверка: `npm run test:virtual:ui` (в DOM 10–20 строк из 4000, прокрутка
  12 шагов ~60 мс, двойной клик ставит в очередь весь список с нужным индексом)

**Экран «Недавнее» (`/recent`)**
- Своей истории прослушиваний у Subsonic нет (`scrobble` — только запись на
  сервер, `getRecentlyPlayed` не существует), поэтому история локальная:
  `src/lib/playHistory.js` + ключ `playHistory` в конфиге (переживает перезапуск,
  чистится при `logout`)
- Прослушивание засчитывается, когда трек звучал ~20 секунд (`MIN_LISTEN_SEC`)
  или доиграл до конца; повтор того же трека не дублируется, а поднимается наверх;
  потолок — 800 записей
- Один плоский список строк: заголовок дня («Сегодня», «Вчера», «12 мая» с годом
  для давних) + треки этого дня, с числом прослушиваний и длительностью; список
  виртуализирован так же, как плейлисты
- Фильтр по дням — «Сегодня / 7 дней / 30 дней / Всё»; рядом «Играть» (вся
  выборка), «Перемешать», «Играть день» у заголовка, «Очистить» с «Вернуть» в тосте
- `getNowPlaying` подключён: на экране показывается полоса «Сейчас играет» —
  что слушает этот же пользователь на других устройствах (обновляется раз в минуту)
- Строка в истории — обычный `.track-row`: обложка, имена исполнителей со ссылками,
  альбом, «сколько назад» + контекст (откуда играли), длительность, крестик
  «убрать из истории» и контекстное меню
- В настройках — переключатель «История прослушиваний» и кнопка «Очистить»;
  выключенный переключатель историю стирает и больше не пишет
- Проверки: `npm run test:play-history` (офлайн) и `npm run test:recent:ui` (Playwright)

## Архив с исходниками

После каждой правки проект пакуется в `spotidrome.zip` (рядом с папкой проекта):

```bash
npm run zip                 # то же самое: bash tools/make-zip.sh
bash tools/make-zip.sh /куда/угодно.zip
```

В архив попадают исходники, `package-lock.json`, `electron/`, `assets/`, nix-файлы
и README — всё, что нужно для сборки. Не попадают `node_modules`, `dist`,
`release` и кэши. Распаковали → `npm install` → `npm run dev` / `npm run dist:linux`.

## Запуск

```bash
npm install
npm start          # Electron + Vite dev-сервер (то же, что npm run dev:electron)
```

Только веб-версия (без Electron — без офлайн-загрузок и медиа-клавиш):

```bash
npm run dev        # http://localhost:5173
```

## Сборка установщика

```bash
npm run dist       # electron-builder → папка release/
```

Собираются: `.dmg`/`.zip` (macOS), `.exe` NSIS + portable (Windows), `AppImage`/`.deb` (Linux).

## Подключение к Navidrome

При первом запуске введите:

- **Адрес сервера** — например `http://localhost:4533` или `https://music.example.com`
  (без `/rest`, без слэша в конце);
- **Пользователь** и **пароль** от Navidrome.

Аутентификация — стандартная схема Subsonic: на каждый запрос генерируется случайная соль
и `token = MD5(пароль + соль)`, сам пароль по сети не передаётся. Учётные данные хранятся
локально в `config.json` внутри `userData` приложения.

CORS: Navidrome не отдаёт `Access-Control-Allow-Origin` для произвольных источников,
поэтому в главном процессе Electron заголовки ответов патчатся через
`session.webRequest.onHeadersReceived`. Это нужно и для эквалайзера — Web Audio требует
CORS-совместимый источник, иначе граф обработки не подключить.

Кнопка **«Посмотреть демо-библиотеку»** на экране входа поднимает локальный мок
(12 исполнителей, ~30 альбомов, плейлисты, синхронный текст, распределённый по длительности трека) —
удобно, чтобы оценить интерфейс без сервера. В демо за текстом на lrclib.net клиент сам не ходит:
кнопка «Искать на LRCLIB» на вкладке «Текст» включает внешний поиск вручную. Реального звука в демо нет: прогресс проигрывается виртуальным таймером.

## Совместимость

Работает с любым сервером Subsonic API 1.16.1+, но рассчитан на Navidrome
(OpenSubsonic-расширения: структурированные тексты, `getTopSongs`, `getArtistInfo2`).
Функции, которых нет на сервере, деградируют мягко — интерфейс не ломается.

Spotidrome не связан со Spotify AB; сходство ограничено визуальным стилем интерфейса.
